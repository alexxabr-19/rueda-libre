Herencia comprobada en DevTools (Styles y Computed) para la etiqueta <p>:

- Propiedad que se hereda: color. El párrafo usa el gris asfalto que puse
  en el body.
- Propiedad que NO se hereda: background-color. También aparece en el body,
  pero se ve apagada (en gris) porque no pasa al párrafo. El fondo crema se
  ve porque es el del body, no porque el párrafo lo haya recibido.


Conflicto del enlace:
Agregué las reglas mencionadas, pero el enlace con la clase activo no se veía verde.
En DevTools (Styles) la declaración color de .activo salía tachada.

Especificidad de cada selector:
- #menu a  = (1, 0, 1)  -> 1 id, 0 clases, 1 etiqueta
- .activo  = (0, 1, 0)  -> 0 id, 1 clase, 0 etiquetas

Causa: un id pesa más que una clase, por eso #menu a gana aunque .activo esté
escrita después.

Solución: cambié .activo por #menu a.activo = (1, 1, 1), que le gana a (1, 0, 1).

Medición del ancho de una tarjeta:
- Con box-sizing: border-box: width = 750.4 px
- Sin border-box (content-box): width = 716.8 px

¿Flex o Grid?

¿Cómo lo hice?: Yo uso Flexbox cuando acomodo elementos en UNA dimensión (una fila o una columna). Y
Uso Grid cuando necesito una cuadrícula de DOS dimensiones (filas y columnas) con
proporciones que yo puedo definir.

1. Portada (inicio): GRID.
   Usé grid-template-columns: 1fr 1fr para dividir el espacio en dos columnas iguales
   (texto y foto). Con align-items: center el texto queda centrado verticalmente.
   Elegí Grid porque quiero definir yo las columnas, sin importar cuánto contenido haya.

2. Galería "Nuestras rutas": GRID.
   Usé repeat(3, 1fr) y gap para tener tres tarjetas del mismo ancho. Elegí Grid porque
   es una cuadrícula: si agrego más rutas, se acomodan en filas nuevas.

3. Reservas: GRID.
   Usé grid-template-columns: 2fr 1fr. El formulario ocupa 2 partes y el aside 1 parte,
   o sea, proporción 2:1. Elegí Grid porque la proporción la defino yo, no el contenido.

4. Formulario: FLEXBOX.
   Son solo dos campos en una fila. Usé display: flex, justify-content: space-between y gap. 
   Elegí Flexbox porque es una sola dimensión.

5. Encabezado: FLEXBOX.
   Es una sola fila: el nombre del negocio y el menú. Usé justify-content y align-items
   para repartirlos y centrarlos verticalmente.

6. Pie de página: FLEXBOX.
   Es una sola fila con tres bloques (marca, contacto y horario). Usé justify-content
   y gap para separarlos. Es una dimensión, por eso usé Flexbox.


Problemas

1. Problema: en reservas.html a 360 px, documento y celular quedaban lado a lado, apretados,
   y sus campos desalineados.
   Solución: dejé en la regla base de .fila flex-direction: column y .campo con
   width: 100%, y moví la fila (row) a la media query de 768 px.

2. Problema: en tarifas.html a 768 px el menú se partía en dos líneas porque el título es largo.
   Solución: en la media query de 768 px puse #menu con flex-wrap: nowrap.

3. Problema: en reservas.html a 768 px el horario de atención quedaba en una lista alta
   y angosta debajo del formulario, y se desperdiciaba el espacio de al lado.
   Solución: en la media query de 768 px puse la lista con display: flex y
   justify-content: space-between para que quede en fila, y en la de 1200 px le puse
   flex-direction: column porque ahí el horario queda en la columna angosta.

CONFLICTOS ENTRE MI CSS Y BOOTSTRAP

1. .galeria y .row
- Qué vi: las tarjetas de rutas se veían angostas, de un tercio del ancho.
- Por qué: mi clase .galeria tenía display: grid y se cargaba después de Bootstrap,
  así que le ganaba al display: flex de .row.
- Cómo lo resolví: quité la clase galeria del HTML y dejé solo la grilla de Bootstrap.

2. Color de los enlaces
- Qué vi: el enlace "Encuéntranos" se veía azul de Bootstrap y no verde de mi marca.
- Por qué: Bootstrap le pone color azul a todos los <a>.
- Cómo lo resolví: agregué en styles.css la regla a { color: var(--verde-ruta); }.
  Como styles.css se carga después de Bootstrap, gana.

3. Altura de las fotos
- Qué vi: las fotos de la flota y las rutas quedaron de alturas distintas.
- Por qué: la clase img-fluid de Bootstrap pone height: auto y ya no tenía mi altura fija.
- Cómo lo resolví: aún estoy mirando para que no quede mal

COMPARATIVA FINAL: CSS PROPIO vs BOOTSTRAP

Líneas de styles.css:
- v1.5 css-propio: 345 líneas.
- v2.0-beta (con Bootstrap): 174 líneas.

Tiempo invertido:
- v1.5 (distribución con Flexbox y Grid propios): 3 horas más o menos.
- v2.0-beta (migración a Bootstrap, incluyendo corregir conflictos):1 hora y 30 minutos más o menos.

Ventajas observadas:
- Las cuadrículas se hacen más rápido y más sencillo con Bootstrap que con Grid.
- Menos css, hay muchas clases de Bootstrap que facilitan las cosas.

Desventajas observadas:
- Bootstrap cambia estilos base (títulos, tablas, márgenes) y hay que corregirlos.
- Hay que aprender los nombres de las clases y revisar la documentación.
- No hay muchos colores y/o estilos disponibles. El margin y padding llegan hasta un límite también en Bootstrap. Toca declarar eso en el css.

Conclusión:
Definitivamente, Bootstrap es una herramienta que proporciona una gran ayuda en el diseño de una página web. Reduciendo tiempo y ahorrando líneas de código
al implementar sus clases. LLevar el css a Bootstrap sí me pareció algo tedioso. Sin embargo, empezar desde 0 con Bootstrap debe ser mucho más cómodo. Eso sí, Bootstrap tiene
falencias como: no tener muchos colores disponibles o que hay que estar pegado a la documentación para tener en cuenta la infinidad de clases que hay. Pero a decir verdad, es una 
excelente herramienta.

Tailwind

Creé el prototipo de Rueda Nocturna utilizando Tailwind CSS, agregando colores, tamaños y espaciados.
En Bootstrap hice el botón con `btn btn-primary`, mientras que en Tailwind utilicé clases como `bg-orange-400`, `text-black` y `p-3`.
La diferencia es que Bootstrap tiene componentes prediseñados y Tailwind permite crear los estilos combinando clases pequeñas.
Fue interesante conocer otra forma de diseñar páginas web. :D

Al revisar el CSS, encontré "bg-orange-400", pero no "bg-pink-500", porque Tailwind solo genera las clases que utilizamos.
